Every rule maps to the test that proves it. A rule with no test is NOT IMPLEMENTED —

**Evidence grade (CONF-2).** The tier names the evidence for the property a rule governs.
`contract` is a test in `tests/Contract/` against the contract fixture: a real Langsys API on an
SDK test clone, reached through `tests/contract-fixture/forwarder.mjs`, vendored byte for byte from
langsys-js-typescript and cited above with the clone's commits. The clone is seeded before the run
from `tests/contract-seeds/`, where every test case has projects of its own; a case confirms
through the API that its seed landed before it acts, and asserts on what the API then holds, read
back through its routes (the catalog, a block's stored content as its owner reads it, and the
hints the clone stored), never on what the SDK sent or on error text. The forwarder adds only
faults and crafted reference lists, and never plays an older server. An absence counts only where
the API would have accepted the action, so a test that shows the SDK holding back first lets the
SDK learn its answer, then drifts its world until the action would be accepted (the case moves to
an address its key's allow-list holds, or its project's owner edits the key), and carries a
control that acts in that world. `mock` is a test against
`tests/Mock/MockHttpClient.php`, which accepts whatever it is given: a row whose property depends on
the server's answer and whose evidence is still `mock` is `provisional`. In-process behaviour
(tokenizing, ids, interpolation, cache keys, what the served bytes contain), cross-implementation
identity fixtures, meta-rules, and "never attempt" clauses proven at the transport seam are tier
`n/a (pure)`, graded on whether breaking the behaviour turns a named test red on **every path** the
rule runs on. A row that is part pure and part answer-dependent takes the grade of its
answer-dependent half; a "never sends" clause is proven at the transport seam. The contract tests
start the forwarder with Node 18 or later and fail without a clone (`tests/README.md`, "Contract
tests"); CI, which has none, runs the `no-clone` suite.

**Grades, and what green means here.** One table, one rule id per row, every id the spec names. Each row carries one
**Status** — `implemented`, `provisional`, `delegated` (bindings only), `partial`, `not implemented`,
`held (strip ruling)`, `waived` (only with the operator's recorded agreement), `n/a (profile: <p>)`
(only where the rule's own Profiles line excludes every profile this SDK claims), or
`n/a (architecture: <reason, and what would make it live>)` — and one **Tier**: `live`, `contract`,
`mock`, `n/a (pure)` or `-`. `implemented` needs `live`, `contract` or `n/a (pure)` and a recorded
mutation; `provisional` needs `mock`. Green is `implemented`, `delegated` and `n/a` only.

**How a row reaches `implemented`.** Every path the rule runs on has a test that turns red under a
recorded mutation, run in a git worktree. A row where one path's mutant stays green is `partial`,
naming the path proven and the path asserted. An answer-dependent row is `implemented` only on
`contract` evidence; one whose tests used only the mock would be `provisional`.

**Historical ids on both rendering paths.** A content block the catalog holds under a historical id is served from it on the page path and the block path alike, an uncategorised one under either category slot; a historical id holding different content is rejected; a historical id is never sent; and a block served from a historical id is **not** queued, because registering it would put a second block under its current id and leave its translations on the old one. Both paths resolve a block through `Client::resolveContentBlockTranslations()`, so they cannot disagree about it. CID-3 grades the lookup and CID-4 the content check. Both rendering paths: `tests/Html/PageTranslatorTest.php::testTranslatePageServesAContentBlockFoundUnderItsLegacyId`, `::testTranslatePageDoesNotQueueALegacyResolvedContentBlock`, `::testPageAndContentBlockPathsAgreeOnALegacyBlock`; and `tests/ClientTest.php::testContentBlockResolvesUnderItsLegacyPipeFormId`, `::testUncategorizedLegacyBlockResolvesUnderTheEmptyCategorySlot`, `::testUncategorizedLegacyBlockResolvesUnderTheSentinelCategorySlot`, `::testLegacyIdResolvingToDifferentContentIsRejected`, `::testLegacyIdIsNeverSentToTheApi`.

## Tokenizer canonicalization

The identity contract every implementation shares. These rules decide what a *phrase* is, and a
content block's `custom_id` is a hash of its phrase list in order — so a disagreement here is not
cosmetic, it re-keys blocks and strands their translations.

Measured against `tests/fixtures/canonicalization-reference.json`, authored by
langsys-js-typescript and adopted byte-identically (`a418fe70:tests/fixtures/canonicalization-reference.json`,

Every row passes.

# Re-derive the blob and the tally together. The target is a COMMIT, not a branch, because a branch
# can move under a file that cites it.
#
#   T=d3846d13f82fc85c5b77bb9502fed3cb84774c66
#   cd ~/Documents/dev/langsys2 && git fetch -q origin \
#     && git rev-parse "$T:docs/sdk-spec.mdx" \
#     && git show "$T:docs/sdk-spec.mdx" > /tmp/spec.mdx
#
# Last run 2026-10-30T01:30:28Z against blob 267ca913 (langsys2 @ d3846d13): exit 0.
#
# python3 - <<'EOF'   (from the repo root; spec at /tmp/spec.mdx)
import re, sys, collections
spec = open('/tmp/spec.mdx').read()
prof = {}
for m in re.finditer(r'^### ([A-Z]+-\d+)\s*—', spec, re.M):
    pm = re.search(r'\*\*Profiles:\*\*\s*(.+)', spec[m.end():m.end() + 600])
    prof[m.group(1)] = pm.group(1).replace('*', '').strip() if pm else ''
ids = list(prof)
def binds(p):
    return ('all' in p) or ('server' in p)
STATUS = re.compile(r'^(implemented|provisional|delegated|partial|not implemented|held \(strip ruling\)|waived|n/a \(profile: [^)]+\)|n/a \(architecture: .+\))$')
TIERS = ('live', 'contract', 'mock', 'n/a (pure)', '-')
occ, grade, errors, intable = collections.Counter(), {}, [], False
for line in open('CONFORMANCE.md').read().splitlines():
    if line.startswith('| Rule | Status | Tier | Evidence |'):
        intable = True
        continue
    if intable and not line.startswith('|'):
        intable = False
    if not intable or line.startswith('|---'):
        continue
    cells = [c.strip() for c in line.strip().strip('|').split('|')]
    found = re.findall(r'\b[A-Z]+-\d+\b', cells[0])
    if len(found) != 1 or '…' in cells[0] or len(cells) != 4:
        errors.append(('not one rule id per row, or not four cells', cells[0]))
        continue
    rid, st, tier, ev = found[0], cells[1], cells[2], cells[3]
    occ[rid] += 1
    grade[rid] = st
    if rid not in prof:
        errors.append(('unknown id', rid))
        continue
    if not STATUS.match(st):
        errors.append(('non-canonical status', rid, st))
        continue
    if tier not in TIERS:
        errors.append(('non-canonical tier', rid, tier))
    if st.startswith('n/a (profile:') and binds(prof[rid]):
        errors.append(('profile n/a on a rule that binds this SDK', rid, prof[rid]))
    if st.startswith('n/a (architecture:') and 'live' not in st:
        errors.append(('architecture n/a without what would make it live', rid))
    if st == 'implemented' and tier not in ('live', 'contract', 'n/a (pure)'):
        errors.append(('implemented needs live, contract or n/a (pure)', rid, tier))
    if st == 'implemented' and 'Mutation' not in ev:
        errors.append(('implemented row records no mutation (CONF-3)', rid))
    if st == 'provisional' and tier != 'mock':
        errors.append(('provisional needs mock', rid, tier))
    if st == 'delegated':
        errors.append(('delegated is for bindings; this is a core', rid))
missing = [i for i in ids if occ[i] == 0]
dup = [i for i in ids if occ[i] > 1]
b = collections.Counter(('n/a' if grade.get(i, '').startswith('n/a') else grade.get(i, '?')) for i in ids)
green = all(grade.get(i, '') in ('implemented', 'delegated') or grade.get(i, '').startswith('n/a') for i in ids)
print(f'rule ids {len(ids)}  one row each {sum(occ[i] == 1 for i in ids)}  missing {missing}  duplicated {dup}')
print('grades', dict(b))
print('errors', errors)
print('GREEN', 'yes' if green else 'no')
sys.exit(1 if (missing or dup or errors) else 0)

## Findings raised against this revision

**`svg` and `math` are treated alike on every route.** SVG `<text>` is visible copy and is
translated; MathML is notation and is not. All three routes that read markup list the same
excluded elements, `script`, `style`, `noscript`, `template` and `math`, with `svg` on none: the
content-block walk (`HtmlParser::NON_PROSE_ELEMENTS`), the page walk
(`PageTranslator::SKIP_ELEMENTS`) and the tokenized-run route (`MarkupTokenizer::OPAQUE_ELEMENTS`).
See the TOK-1 row.

**A phrase wrapped in inline markup keeps its markup on the page path.** In
`<li><a href="#">Label</a></li>` the translation replaces the text node that carries the phrase,
found at any depth, so the `<a>` stays in the served bytes. Nav items, card links, buttons and
table cells are all this shape. `tests/Html/PageTranslatorTest.php::testAPhraseWrappedInInlineMarkupKeepsItsMarkup`

**libxml2 reads these inputs differently by version, and the SDK's reading does not depend on
it.** libxml2 2.15.2, as Ubuntu 26.04 ships it, reads a textarea or title body as text, as parse5
7.3.0 does, and agrees on both raw-text rows; lxml on libxml2 2.14.6 does too, while Nokogiri on
2.13.9 behaves like 2.9.13. No libxml2 measured foster-parents: 2.9.13, lxml's 2.14.6 and 2.15.2
all keep the stray `<b>` and the loose text inside the table. The fixture's `libxml2_raw_bodies`
column holds 2.15.2's answers where they differ, and `Html\Document::readsRawBodies()` asks libxml2
once per process which reading it has. Where a parse differs, the two identities are exposed
differently, as the table above measures: a raw-text body moves both a `Phrase` key and a content
block's id, while foster parenting moves only the `Phrase` key, its two rows having equal block ids.
Through `Document::load()` the SDK gives the same tokens, keys and block ids on 2.9 and on 2.15, so a
host's libxml2 version moves none of them.

### C0 controls

TOK-2 at `aff89a98` specifies the strip, and this SDK performs it at its one canonicalization site.

| Item | Status | What it is |
|---|---|---|
| C0 strip | implemented | The 28 C0 controls — U+0001–0008, U+000B, U+000C, U+000E–001F — are deleted from every id input and catalog key, on register and lookup alike, before whitespace collapses. TAB, LF and CR are not stripped and still collapse; U+007F and the C1 range are kept |
| C0 parser split | measured | libxml2 2.9.13 drops the same 28 from DOM text, including as character references (`a&#x1C;b&#x0B;c` yields `abc`), while keeping TAB, LF and CR. parse5 7.3.0 and happy-dom 20.10.2 keep all 28. Measured on the raw `DOMDocument`, with no SDK code in the path, so a text-node test of the strip passes here for the parser's reason |
| Strip tests | implemented | Asserted on the canonicalization function directly, a string in and a string out, and on the code-registered path (`tests/Html/ControlCharacterStripTest.php`); the one DOM-level vector that cannot pass vacuously, a translatable attribute holding a raw U+001C, is the shared fixture's `fs-in-attr` row and passes on both DOM paths |
| VT and FF | not implemented | Removed by the strip, not collapsed: `a\x0Bb` becomes `ab`, not `a b` |

**Residuals, independent of the strip — measured on libxml2 2.9.13.**

- A C0 **character reference** inside an **attribute** value truncates the rest of the value: `title="a&#x1C;b"` yields `a`.
- A **raw** C0 character inside an attribute value is **kept**: `title="a[U+001C]b"` yields all three characters.
- A **raw NUL** in text becomes U+0020: `<p>a[U+0000]b</p>` yields `a b`.
- `&#0;` in text is **dropped**: `<p>a&#0;b</p>` yields `ab`.

### CID-4's set comparison

CID-4's content check compares phrases as a set, and that is conforming. This SDK's catalog returns a content
block as a map keyed by source phrase, so when the guard runs only the set of phrases is
recoverable, not their order. CID-4 at blob `267ca913` reads *"Compare phrases in order where the
representation preserves order; a set comparison is conforming where it does not"*, so the CID-4
row is graded `implemented` on that text. A set guard defeats every known collision mode, all of
which are collisions over differing content; it is strictly weaker in one case, two blocks whose
phrases match as a set and differ in order, which are distinct under CID-1 and indistinguishable
to it.

## Known gaps

No rule is `provisional`, `partial`, `not implemented`, `held` or `waived` (*Computed summary*).
Every rule that binds this SDK is `implemented` or `n/a` on architecture, and each architecture
row names what would make it live.

A send that fails in the shutdown flush is logged and not retried: nothing runs after that flush
to retry it, and the queue it keeps ends with the process (REG-3, REG-8). A failed send records
nothing as registered, so the next request that misses the same content queues it again (GATE-5).

The template's per-rule **Revision** column is not populated. The hashes are a lookup rather than
a derivation: `sectionRevisions` under `pages.sdk-spec` in langsys-docs'
`internal-docs/internal-docs.json`, which `npm run build:internal-docs` builds there.

## Stale-phrase check

The summary script above proves the COUNTS are right. This proves the PROSE is — that no
sentence still asserts something a later revision made false.

Fixed strings with expected counts, not a regex sweep, and the expectation is asserted rather
than eyeballed. The count is of matching LINES (`grep -c`), not of occurrences: a line that names a blob
twice counts once. The `sed` truncation matters: without it this section's own phrase list is
counted as occurrences and every expectation fails - the check would be measuring itself. A retired
phrase (a claim, a test or class name, a table shape, a hash) is expected at 0, so the check fails
the moment it comes back; a phrase the file has to keep is listed at its count, so a reader can
tell a kept occurrence from a missed one.

The check covers **CONFORMANCE.md, CHANGELOG.md and tests/fixtures/README.md**, because a stale
claim is as damaging in the file customers read as in the one reviewers do.

**Limit of the instrument, stated where it is used:** it matches FIXED STRINGS. A paraphrase of a retired claim - "has never had a skip list" in place of the sentence it retired - passes. It catches a sentence coming back, not an idea coming back.
