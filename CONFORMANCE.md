**Evidence grade (CONF-2).** The tier names the evidence for the property a rule governs.
`contract` is a test against the shared contract fixture in `tests/contract-fixture/`, vendored byte
for byte from langsys-js-typescript at tree `542f57f5ffcb9038db1b7411152b7e31b96cb269`. It refuses requests the way
the server does and holds state, so a `contract` test asserts on what the server accepted, read
back, and never on what the SDK sent or on error text. An absence counts only where the double
would have accepted the action, so a test that shows the SDK holding back first lets the SDK learn
its answer, then drifts the double's world until the action would be accepted, and carries a
control that acts in that world. `mock` is a test against
`tests/Mock/MockHttpClient.php`, which accepts whatever it is given: a row whose property depends on
the server's answer and whose evidence is still `mock` is `provisional`. In-process behaviour
(tokenizing, ids, interpolation, cache keys, what the served bytes contain), cross-implementation
identity fixtures, meta-rules, and "never attempt" clauses proven at the transport seam are tier
`n/a (pure)`, graded on whether breaking the behaviour turns a named test red on **every path** the
rule runs on. A row that is part pure and part answer-dependent takes the grade of its
answer-dependent half. The contract tests start the fixture with Node 18 or later and are skipped
without it.

### C0 controls

TOK-2 at `286dcfe4` specifies the strip, and this SDK performs it at its one canonicalization site.

| Item | Status | What it is |
|---|---|---|
| C0 strip | implemented | The 28 C0 controls — U+0001–0008, U+000B, U+000C, U+000E–001F — are deleted from every id input and catalog key, on register and lookup alike, before whitespace collapses. TAB, LF and CR are not stripped and still collapse; U+007F and the C1 range are kept |
| C0 parser split | measured | libxml2 2.9.13 drops the same 28 from DOM text, including as character references (`a&#x1C;b&#x0B;c` yields `abc`), while keeping TAB, LF and CR. parse5 7.3.0 and happy-dom 20.10.2 keep all 28. | Strip tests | implemented | Asserted on the canonicalization function directly, a string in and a string out, and on the code-registered path (`tests/Html/ControlCharacterStripTest.php`); the one DOM-level vector that cannot pass vacuously, a translatable attribute holding a raw U+001C, is the shared fixture's `fs-in-attr` row and passes on both DOM paths |
| VT and FF | not implemented | Removed by the strip, not collapsed: `a\x0Bb` becomes `ab`, not `a b` |

**Residuals, independent of the strip — measured on libxml2 2.9.13.**

- A C0 **character reference** inside an **attribute** value truncates the rest of the value: `title="a&#x1C;b"` yields `a`.
- A **raw** C0 character inside an attribute value is **kept**: `title="a[U+001C]b"` yields all three characters.
- A **raw NUL** in text becomes U+0020: `<p>a[U+0000]b</p>` yields `a b`.
- `&#0;` in text is **dropped**: `<p>a&#0;b</p>` yields `ab`.

**1. ICU-1/2/3 were met by the interpolator and defeated by the public path — FIXED.** `Client::interpolate()`

`translate()` against a catalog value of `{count, plural, one {# item} other {# items}}`:

```

```

*Resolved:* the short-circuit in `Client::interpolate()` is removed, and the interpolator's own

**2. CID-4 was unimplementable as written against a phrase-keyed catalog — ADOPTED, spec `a37b0288`.** The rule requires
comparing `(category, ordered phrases)`. This SDK's catalog returns a content block as a map keyed
by source phrase, so **order is not recoverable at attach time** — only the set is. The guard is
therefore set-based, which still defeats every known collision mode (all are collisions over
differing *content*), but it is strictly weaker than the rule: two blocks with identical phrases in
different orders are distinct under CID-1 and indistinguishable here. Either the rule should say
"ordered where the representation preserves order", or the catalog must carry order.

*Resolved:* the rule now reads "ordered where the representation preserves order; a set
comparison is conforming where it does not", and names the case where a set guard is
strictly weaker. The revision this file is written against is now bumped (blob `5c5c0723`), so the row is
re-graded `provisional` and the status and the cited revision agree.

**3. HINT-10/11 were marked `browser, server` while HINT-2 forbids server SDKs from reporting — ADOPTED, spec `a37b0288`.** If a
server SDK never reports, it can never transmit a credential-bearing URL, so the rules are
vacuously satisfied and cannot be tested here. Either the profile line is over-broad or HINT-2's
scope has changed; recorded as `n/a` on the HINT-2 reading rather than claimed as met.

*Resolved:* all three rescoped to `browser`. The `n/a` rows above now match the spec
